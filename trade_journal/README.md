# 📓 ژورنال معاملات

هر روزِ معاملاتی یک پوشه با نام `YYYY-MM-DD` می‌گیرد. محتوای واقعی این پوشه‌ها
(P&L، شماره تیکت، تقویم خبری) **در مخزن گیت قرار نمی‌گیرد** و فقط روی دستگاه محلی
نگهداری می‌شود؛ این فایل صرفاً ساختار را توضیح می‌دهد.

```
trade_journal/
└── YYYY-MM-DD/
    ├── trades.csv                       # یک ردیف برای هر معاملهٔ بسته‌شده
    ├── NNN_<position_id>_<symbol>_<dir>.md   # جزئیات هر معامله + «درس‌ها»
    └── news_calendar.md                 # رویدادهای پرتأثیر آن روز (به وقت ایران)
```

## ستون‌های `trades.csv`

| ستون | توضیح |
|---|---|
| `ticket`, `position_id` | شناسه‌های سفارش/پوزیشن در متاتریدر |
| `symbol`, `direction` | نماد و جهت (`BUY`/`SELL`) |
| `entry_time_utc`, `entry_price` | زمان و قیمت واقعی ورود (از `history_deals_get`) |
| `exit_time_utc`, `exit_price` | زمان و قیمت واقعی خروج |
| `sl`, `tp`, `lot` | حد ضرر، حد سود، حجم |
| `profit_usd` | سود/زیان تحقق‌یافته به دلار |
| `close_reason` | `TP_HIT` / `SL_HIT` / `MANUAL_CLOSE_*` / `TIME_STOP` |
| `setup_quality` | کیفیت ستاپ در لحظهٔ ورود: `HIGH` / `MEDIUM` / `LOW` |
| `rr_planned` | نسبت ریسک‌به‌ریوارد برنامه‌ریزی‌شده |
| `notes` | روایت کوتاه ستاپ و نتیجه |

## قواعد

- فقط معاملاتی که **خودِ ایجنت** باز کرده ثبت می‌شوند (تشخیص با `magic` / `comment`).
  معاملات دستی کاربر فقط برای مرور بررسی می‌شوند، ردیف نمی‌گیرند.
- بعد از بسته‌شدن هر پوزیشن، پیش از تحلیل بعدی: دیلِ بسته‌شدن واقعی خوانده می‌شود،
  یک ردیف به `trades.csv` اضافه می‌شود و فایل `.md` جزئیات نوشته می‌شود.
- پوزیشن‌های **بلندمدت** (تیکت با مجیک استثناء) جدا از بودجهٔ اسکلپ روز ثبت می‌شوند.
